# Component guidance · proposed

- **Navigation:** Use native links for destinations and visible text for the current view. Preserve the site's layout conventions and legacy paths.
- **Forms:** Use persistent labels, clear optional fields, one main action, and errors that explain what to change without losing input. Use a visible focus ring, aim for 44 px touch targets, and keep status independent of color.
- **Layouts:** Check narrow phones, desktop, keyboard navigation and zoom. Let cards stack before fields get cramped. Keep schedule-specific density where it helps the task.
- **Photography:** Use intentional crops, meaningful alt text, and only cleared public assets. Keep photo notes and BuildFest treatments distinct. Review metadata before adding assets.
- **Motion:** Prefer immediate feedback for form and navigation states. Use motion only if it clarifies what changed, respect reduced motion, and avoid autoplay or decorative delays.
