# Studio executor: setup after owner approval

PR B enables a single copy slot: the Personal homepage projects heading. Studio still saves all other requests for review. The executor cannot add files, edit markup, modify workflows, follow URLs from prompts, or run generated commands. The only model artifact is a plain-text replacement for the existing heading. The publisher independently rebuilds that patch from the pinned source. This is a bounded fallback, not a general Codex sandbox.

The [Agents API session schema](https://developers.openai.com/api/reference/resources/beta/subresources/agents/subresources/sessions/methods/create) does not document a caller-configurable spend ceiling covering both agent model calls and hosted sandbox charges. Its [session budget error](https://developers.openai.com/api/docs/guides/agents-api/errors) does not establish such a ceiling. This slice uses a single tool-free [Responses request](https://developers.openai.com/api/reference/resources/responses/methods/create), plus an isolated Cloud Run validator. No Agents API or OpenAI sandbox entitlement is needed for the fallback. OpenAI project access has not been tested.

## Configure staging first

1. In OpenAI Platform create a dedicated billing project. Confirm access to `gpt-4.1-mini-2025-04-14`; restrict the project to that model where available. Create a restricted project key with Responses write only and store it as dispatcher secret `STUDIO_OPENAI_KEY`. Keep it out of Studio web, the validator and GitHub. Check the [published snapshot limits and rates](https://developers.openai.com/api/docs/models/gpt-4.1-mini) and confirm standard, non-regional billing with no pricing uplift. Recheck rates before activation and disable dispatch if they change. Platform project alerts are supplemental.
2. Create a private [GitHub App](https://docs.github.com/en/rest/apps/apps#create-an-installation-access-token-for-an-app) with webhooks disabled and repository Contents and Pull requests read/write, plus the default Metadata read. Install on **only** `enaz333/zane-websites`. No Workflows, Actions, deployment or administration access; no bypass of main protection. Record the numeric App ID and installation ID. Store the generated PEM as the dispatcher secret `STUDIO_GITHUB_PRIVATE_KEY`, never in the validator. The publisher requests an installation token limited to this repository and those permissions. The dispatcher is trusted code and hosts the publisher module; the model and validator cannot invoke that module.
3. From a reviewed checkout, fetch main and select its full commit SHA. Run `context=$(sh sites/studio/executor/prepare-image.sh "$BASE_SHA")`. Build the provided Dockerfile from that context with `--build-arg STUDIO_CHECK_BASE="$BASE_SHA"`, using a Linux image supported by Cloud Run. The context contains a Git archive of that exact revision and two reviewed runner files; `npm ci` runs during build. Push the image to a private Artifact Registry and [deploy the image by digest](https://docs.cloud.google.com/run/docs/deploying) with port 8080, request timeout 310 seconds, one request per instance, max one instance, min zero, and no traffic to old revisions. Use a dedicated runtime service account with no project grants. Give it read access only to a Secret Manager secret containing a random bearer token of at least 32 bytes; map that secret to `STUDIO_CHECK_SECRET`. Grant the same token to the dispatcher. The `run.app` URL accepts requests from the Internet; the process rejects unauthorized requests before reading their body. Do not expose it until the secret is configured. Apply restricted outbound networking if available; dependency installation happens at build time. The checker invokes only fixed repository commands with a clean child environment, and accepts only text for the one slot. Never build from a task branch.
4. Use a **separate Studio staging D1** and an owner-only Cloudflare Access app. Apply migrations 0001–0003 to that staging database. Configure the staging Studio web Worker with its own D1 and the usual four Access runtime secrets from the [private release guide](studio-release.md). Keep Workers.dev, previews and routing off until the staging Access hostname is protected. Add `STUDIO_QUEUE_ENABLED=true` to the **web Worker only** once testing the queue. Leave the approved production release workflow and existing hostname alone.
5. Copy `sites/studio/executor/wrangler.json` to an ignored file such as `sites/studio/executor/config.staging.json` (add it to your local Git exclude first), name the Worker `zane-studio-dispatch-staging`, and keep both public URL flags false. Add the staging D1 binding named `DB` with `migrations_dir: "../migrations"`. Set non-secret `vars` below and add `triggers: { "crons": ["*/2 * * * *"] }` after testing the disabled Worker. Put both API credentials and the checker token into Worker secrets through Wrangler secret input or the dashboard. Never place them in config, CLI arguments, snapshots or logs.

| Dispatcher variable | Value |
| --- | --- |
| `STUDIO_BASE_SHA` | Full reviewed main SHA used to build the validator |
| `STUDIO_CHECK_ORIGIN` | Validator's exact HTTPS `run.app` origin, without a path |
| `STUDIO_GITHUB_APP_ID`, `STUDIO_GITHUB_INSTALLATION_ID` | Numeric IDs |
| `STUDIO_RATE_CARD` | `gpt-4.1-mini-2025-04-14:standard:0.40:1.60` after verifying rates |
| `STUDIO_RUN_MICROS`, `STUDIO_MONTH_MICROS` | Optional USD millionths; defaults 2000000 and 20000000, can only be lowered |
| `STUDIO_EXECUTION_ENABLED` | Set to `true` only for the approved test |

The dispatcher never uses inbound callbacks. Cron reclaims an expired lock, retries safe operations and reconciles GitHub from a deterministic branch and verified diff. A model request with an unknown outcome is never replayed. If GitHub remains unavailable after the deadline, the task remains reserved and reconciling until GitHub can report whether the PR exists. Existing work is recovered before claiming new work. Cancellation is available until claim. ASAP controls ordering; economy waits at least 15 minutes. Neither is a delivery promise. A queued task blocked by the monthly ledger remains queued and can be cancelled.

## Budget and testing

Each claimed task reserves $0.419440 against the UTC month before any model call. This uses the entire documented context window at uncached standard rates plus 256 output tokens; the actual prompt is additionally limited to 64 KB. The transaction also admits at most one active execution. Reservations are retained even on failure or uncertain billing, so no speculative refund permits another call. Reported token counts are retained when available; they are not billed dollar amounts. New calls stop around month rollover. The caps bound Studio's modeled AI usage under the reviewed rate card; they are not provider-enforced or total infrastructure limits. Cloud Run, build/registry, Workers and D1 may bill separately. Never reuse the project's key for other workloads.

Run the [README checks](../README.md) and the dispatcher bundle dry run: `npx --no-install wrangler deploy --dry-run -c sites/studio/executor/wrangler.json`. The Node integration test uses D1 and fixture OpenAI, validator and GitHub responses; it simulates a lost reply after draft creation. For a container smoke test run the built image locally with a synthetic `STUDIO_CHECK_SECRET`. POST to `/check` with that bearer token and JSON `{"base":"<BASE_SHA>","replacement":"Selected projects"}`. Expect `passed: true` and a SHA-256 digest. Missing credentials must return 403; a wrong base or markup must return 400.

For the first approved live test set both budget variables to `419440` to admit a single task in that UTC month. Start with an empty staging queue and both Macs offline. From the phone open protected Studio staging, choose Edit → Personal site → `/`, check ASAP and enter “Change the projects heading from ‘A little of everything.’ to ‘Selected projects’.” Refresh Activity until the genuine draft link appears. Verify GitHub shows the pinned SHA as the sole commit parent, only the intended heading changed, and the draft is open with checks passed in Activity. Do not merge or deploy it. Disable dispatch after the test. Only repeat on the production Studio hostname after separately approving its release, D1 binding, and activation.

For rollback disable web queue intake and dispatcher scheduling/activation; retain migration 0003 and its ledger. Restore the prior web Worker using the protected Studio procedure if needed. Never manually requeue a task with an unknown model or publish outcome. Reconcile the deterministic branch and PR before any intervention.
